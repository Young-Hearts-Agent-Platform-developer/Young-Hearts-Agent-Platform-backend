# 数据清洗与解析自动化验证 研究报告

## Phase 2: 多格式文档解析与清洗主流程实现与自动化验证一体化方案

### 目标
- 实现多格式文档解析（优先 unstructured，兜底其他工具），并确保主流程的每个分支都能被精准、可靠地自动化验证。
- 集成 langchain Loader/Parser/切片，输出结构化块。
- 实现基础清洗（去噪、去重、格式标准化、PII 检测与脱敏），并通过自动化测试验证其准确性和可扩展性。

### 实现与验证步骤

1. **主流程实现**
      - 在 app/knowledge/clean_parse.py 中实现 parse_and_clean_entry，支持 PDF、Word、TXT、HTML、图片等多格式输入。
      - 优先采用 unstructured.partition_xxx 进行解析，遇异常时自动切换 pdfplumber、python-docx、pytesseract 等工具兜底。
      - 使用 langchain TextSplitter 对文本切片，补全元数据。
      - 实现基础 PII 检测（如手机号、身份证、邮箱、地址等，正则可自定义扩展），所有扩展规则需通过统一接口注册与管理，脱敏替换为 [MASK]，并记录日志。
      - 清洗流程支持去重、去噪、格式标准化。

2. **自动化验证设计**
                  - 所有测试用例所需的文档样本统一存放于 tests/data/ 目录下，需覆盖如下格式类型：PDF、Word（.docx）、TXT、HTML、图片（.png/.jpg）。
                  - 文件命名规范如下，便于开发者准备和识别：
                        - test_pii_phone.pdf：包含手机号的PDF文档
                        - test_pii_idcard.docx：包含身份证号的Word文档
                        - test_pii_email.txt：包含邮箱的TXT文档
                        - test_pii_address.html：包含地址信息的HTML文档
                        - test_pii_bankcard.png：包含银行卡号的图片
                        - test_empty.txt：空文本文件
                        - test_invalid.docx：损坏或格式错误的Word文档
                        - test_mixed_pii.pdf：包含多种PII的PDF文档
                  - 开发者可根据上述类型和命名规范准备验证样例，便于自动化测试脚本加载和断言。
      - 在 tests/test_knowledge_service.py 或 tests/test_knowledge_api.py 中，使用 pytest+fixtures 自动遍历 tests/data/ 下的样本文件，调用 parse_and_clean_entry。
      - 对每个样本，断言：
        - 输出结构化块的数量、内容、元数据是否符合预期
        - PII 是否被正确脱敏，且可通过自定义规则扩展
        - 异常文件是否返回兜底提示，且日志内容为复核友好表述（如“文档第3行检测到手机号，已替换为[MASK]”）
      - 日志内容需转译为复核人员可理解的表述，便于人工审核。
      - 对于 PII 检测规则，测试用例可通过参数化方式传入自定义正则，验证扩展性。
      - 对外部依赖（如 OCR、网络请求）可用 mock/stub 保证测试稳定性。

3. **成功标准**
      - 单元测试和集成测试覆盖多格式解析、PII 检测、异常兜底等主流程所有分支。
      - pytest 全部通过，自动化验证文件放在 tests 目录下。
      - 日志内容为复核友好表述，便于人工审核。

### 关键代码片段建议
- 使用 pytest+fixtures 管理测试数据和环境。
- 断言结构化输出的字段、内容、PII 替换位置。
- 捕获异常并断言返回兜底提示。
- 日志内容示例断言：
  - "文档第3行检测到手机号，已替换为[MASK]"
  - "文件格式不支持，已返回兜底提示"

## 当前实现分析

### 验证目标

- 多格式文档解析（PDF、Word、TXT、HTML、图片等）均能被 parse_and_clean_entry 正确处理。
- PII 检测与脱敏功能能准确识别并替换敏感信息，且支持自定义扩展规则。
- 解析异常（如损坏文件、格式不支持、内容为空）能被兜底处理并记录日志。
- 输出结构化块格式、元数据、切片等均符合预期。
- 日志内容可供复核人员直接理解。

### 推荐验证方法

1. **单元测试**：对 parse_and_clean_entry 及其子流程进行输入输出验证。
2. **集成测试**：模拟 ingest/rag_pipeline 调用主流程，验证端到端效果。
3. **边界与异常用例**：如空文件、极大/极小文件、混合格式、PII 边界值、格式错误等。
4. **日志与脱敏验证**：检查日志文件/对象，确保 PII 替换和异常记录无遗漏，且日志内容为复核友好表述。
5. **Mock/Stub**：对外部依赖（如 OCR、网络请求）可用 mock/stub 保证测试稳定性。

### 测试文件来源与管理

- 所有测试用例所需的文档样本（PDF、Word、TXT、HTML、图片等）应统一存放于 tests/data/ 目录下。
- 文件命名应体现测试目标（如 test_pii_phone.pdf、test_empty.txt、test_invalid.docx 等）。
- 新增或修改测试用例时，需同步维护该目录下的样本文件。

### 自动化验证流程

- 测试用例通过 pytest 实现，自动遍历 tests/data/ 下的样本文件，调用 parse_and_clean_entry。
- 对每个样本，断言：
  - 输出结构化块的数量、内容、元数据是否符合预期
  - PII 是否被正确脱敏，且可通过自定义规则扩展
  - 异常文件是否返回兜底提示，且日志内容为复核友好表述
- 日志内容如“发现手机号，已脱敏”应转译为“文档第X行检测到手机号，已替换为[MASK]”，便于复核人员理解。
- 对于 PII 检测规则，测试用例可通过参数化方式传入自定义正则，验证扩展性。

## 核心流程（测试验证视角）

```
[测试文档样本] → [parse_and_clean_entry] → [结构化块输出]
         ↓

         ↓
   [异常/兜底分支]
         ↓
   [复核友好日志/返回值断言]
```

## 架构洞察

- 测试用例应覆盖所有主流程分支（正常、异常、边界），但暂不需对每种格式的主流变体做全覆盖。
- PII 检测规则需支持自定义扩展，所有扩展规则需通过统一接口注册与管理，测试用例应验证其可插拔性。
- 日志内容需面向复核人员友好转译，便于人工审核。
- 测试数据集中管理，便于回归和扩展。

## 潜在风险和边缘情况

- 部分格式（如图片/OCR）依赖外部环境，需 mock 或容错。
- PII 正则可能误判/漏判，需持续补充测试用例。
- 大文件/批量处理场景下性能与稳定性需关注。
