## 功能概述
为后端核心服务（Auth, User, Consultation）建立完整的自动化测试体系。
重点验证：
1. **鉴权机制**：Session ID 生成、Cookie/Header 传递、Session 过期。
2. **权限隔离**：不同角色的资源访问权限（普通用户 vs 管理员）。
3. **业务逻辑**：用户注册、登录、信息修改、咨询会话管理及流式对话。

## Phase 1: 基础设施建设 (Fixtures & Base Tests)

### 目标
搭建 Pytest 测试框架基础，实现数据库生命周期管理和通用用户登录状态注入。

### 修改文件清单
|文件路径|修改类型|说明|
|---|---|---|
|`tests/conftest.py`|新建|定义 `db`, `client`, `normal_user_auth` (Fixture), `admin_auth` (Fixture)|
|`tests/test_health.py`|新建|简单的健康检查测试，验证环境连通性|

### 具体变更
#### tests/conftest.py
- **DB Fixture**: 每次测试前创建表，测试后回滚或重建。
- **Client Fixture**: 封装 `TestClient`。
- **User Fixtures**:
    - `normal_user`: 预置一个普通用户。
    - `admin_user`: 预置一个管理员用户。
- **Auth Fixtures**:
    - `normal_user_token`: 登录普通用户，返回带 Session Cookie 的 Headers。
    - `admin_token`: 登录管理员，返回带 Session Cookie 的 Headers。

### 成功标准
- [ ] `pytest tests/test_health.py` 运行通过。
- [ ] Fixture 能正确在数据库中创建及清理测试数据。

## Phase 2: Auth 会话管理测试

### 目标
覆盖登录、注册、注销及 Session 安全性测试。

### 修改文件清单
|文件路径|修改类型|说明|
|---|---|---|
|`tests/test_auth.py`|新建|包含登录、注册、注销、Me接口测试|
|`tests/test_auth_security.py`|新建|包含密码错误、账号不存在、以及简单的 Session 过期模拟测试|

### 具体变更
#### tests/test_auth.py
- 测试 `/auth/register`:
    - 正常注册。
    - 尝试注册 `admin` 角色（预期 403）。
- 测试 `/auth/login`:
    - 验证 Response Cookie (`session_id`)。
    - 不同 User-Agent (Web/App) 的返回格式差异。
- 测试 `/auth/me`:
    - 验证敏感字段（如 phone）根据角色脱敏。

### 成功标准
- [ ] 注册/登录/注销 主流程测试通过。
- [ ] 非法角色注册被拦截。
- [ ] 未登录访问受保接口返回 401。

## Phase 3: User & Consultation 核心业务测试

### 目标
验证用户资料修改及咨询会话的 CRUD 与权限隔离（RLS）。

### 修改文件清单
|文件路径|修改类型|说明|
|---|---|---|
|`tests/test_user_service.py`|新建|测试 `update_me` 及数据一致性|
|`tests/test_consultation.py`|新建|测试会话创建、列表隔离、Sse Chat|

### 具体变更
#### tests/test_user_service.py
- 测试 `PUT /auth/me`:
    - 修改昵称成功。
    - 尝试修改 `password`/`roles` 字段（预期忽略或报错）。

#### tests/test_consultation.py
- **会话隔离测试**:
    - 用户 A 创建会话 S1。
    - 用户 B `GET /consult/sessions` 列表不包含 S1。
    - 用户 B `GET /consult/sessions/{S1_ID}` 返回 403/404。
    - 管理员 `GET /consult/sessions/{S1_ID}` 返回 200。
- **聊天接口测试**:
    - `POST /consult/chat`: 测试 SSE 流式响应结构（需解析 `event: message`, `event: done`）。
    - 验证数据库中 Message 是否正确持久化。

### 成功标准
- [ ] 用户仅能修改属于自己的资料。
- [ ] 普通用户无法查看他人会话数据。
- [ ] 管理员可查看任意会话。
- [ ] `/consult/chat` 接口能正确返回流式数据并保存记录。
