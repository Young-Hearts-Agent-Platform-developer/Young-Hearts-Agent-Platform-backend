## 研究问题

如何分阶段，基于 LangChain 实现 RAG？（第一阶段暂不考虑知识库，仅实现简单 AI 问答）

## 发现摘要

- 第一阶段可仅用 LangChain 的 LLM 接口实现基础 AI 问答，无需知识库与向量检索。
- 后续阶段可逐步引入文档检索、向量数据库、切片与审核等模块，逐步演进为完整 RAG。
- LangChain 支持链式调用，便于后续平滑升级。
- 项目结构建议预留 rag/ 目录，便于后续扩展。

## 当前实现分析

### 第一阶段（仅 AI 问答，无知识库）
- 仅需集成 LangChain 的 LLM（如 OpenAI、Qwen、ChatGLM 等）接口。
- 用户问题直接传递给 LLM，返回生成结果。
- 可通过 app/rag/service.py 提供统一的 ask(query) 方法。
- API 层（如 chat.py）直接调用 rag_service.ask()。
- 无需文档检索、向量数据库、知识审核等复杂流程。

### 核心流程

```
用户请求 → API 层 (chat.py) → rag_service.ask(query) → LangChain LLM → 返回答案
```

### 关键代码片段

- app/rag/service.py
  - 实现 ask(query) 方法，内部调用 LangChain LLM。
- app/api/v1/routes/chat.py
  - 定义 /chat/ask 路由，调用 rag_service.ask。

## 架构洞察

- LangChain 的链式结构便于后续插入检索、切片、审核等环节。
- 预留 rag/ 目录和 service 层接口，后续升级无缝。
- 第一阶段可极简上线，快速验证 LLM 能力。

## 潜在风险和边缘情况

- 仅 LLM 问答阶段，答案无可溯源，存在幻觉风险。
- 无法利用专业知识库，回答准确性依赖模型本身。
- 后续升级需考虑接口兼容性。
