## 研究问题

知识库及RAG 功能实现的完整性

## 发现摘要

当前知识库与 RAG 模块已具备基础的端到端能力，包括知识条目的 CRUD、基于 Celery 的异步文档处理（切片、向量化）、基于风险等级的差异化切片策略（高/低风险直接切片，中风险使用父子文档检索），以及在咨询会话中集成 RAG 检索。
**最新进展**：文件上传接口已实现（支持纯文本和文件上传），关系型数据库中的切片模型（`KnowledgeChunk`）已启用（切片数据同步持久化到 MySQL），检索来源已在会话中持久化并通过 SSE 返回给前端。
**当前缺口**：多模态解析（如 PDF、图片、音视频等）仍缺失，目前仅作为纯文本处理。

## 当前实现分析

### 核心流程

1. **知识录入与发布**：
   - 用户通过 `/items` 接口创建知识条目，或通过 `/upload` 接口上传纯文本/文件。
   - `/upload` 接口会将文件保存到 `./data/raw_data`，并创建状态为 `published` 的知识条目。
   - 当条目状态变更为 `published` 时，`KnowledgeService` 会触发 Celery 异步任务 `process_knowledge_document`。
2. **异步文档处理**：
   - 任务读取文档内容，目前仅支持纯文本解析（多模态解析为 TODO）。
   - 根据文档的 `risk_level` 采用不同的切片策略：
     - **中风险**：使用 `ParentDocumentRetriever`，将父块存入本地文件系统（`LocalFileStore`），子块存入 ChromaDB。同时，将父切片和子切片持久化到 MySQL 的 `KnowledgeChunk` 表中，并建立父子关联。
     - **高/低风险**：直接使用 `CustomSplitter` 切片，并将结果存入 ChromaDB。同时，将独立切片持久化到 MySQL 的 `KnowledgeChunk` 表中。
3. **RAG 检索与生成**：
   - 用户在咨询会话中发送消息，`/chat` 接口调用 `async_chat_with_rag`。
   - `retrieve_context` 首先在 ChromaDB 中进行相似度检索，获取相关子块。
   - 如果子块属于中风险文档（有父文档 ID），则从 `LocalFileStore` 中提取父文档作为上下文；否则直接使用子块。
   - 组装上下文后，结合角色 Prompt 和用户 Query，调用大模型生成流式回复。
   - `async_chat_with_rag` 会提取检索来源（`sources`），通过 SSE 返回给前端，并在会话结束时调用 `save_ai_message_and_generate_topic` 将其持久化到数据库中。

## 架构洞察

- **灵活的切片策略**：系统根据文档的风险等级（`risk_level`）动态选择切片策略，中风险文档采用父子文档检索（Parent-Child Retrieval）以保留更多上下文，高/低风险文档则采用直接切片，这种设计在检索精度和上下文完整性之间取得了较好的平衡。
- **检索回退机制**：`retrieve_context` 在尝试获取父文档失败时，会自动回退使用检索到的子块，这使得系统能够兼容不同风险等级文档的混合检索。

## 潜在风险和边缘情况

- **距离与相似度转换风险**：在 `retrieve_context` 中，当 ChromaDB 不支持 `relevance_scores` 时，代码使用 `max(0.0, 1.0 - score / 2.0)` 将 L2 距离转换为相似度得分。这是一个简单的线性转换，可能无法准确反映实际的语义相似度，导致低于阈值的无关文档被召回，或相关文档被过滤。
- **数据一致性风险**：虽然切片数据已同步到 MySQL 的 `KnowledgeChunk` 表，但如果向量数据库（ChromaDB）或本地文件系统（`LocalFileStore`）与 MySQL 之间发生部分写入失败，可能会导致数据不一致。目前缺乏定期的数据一致性校验机制。

## 开放问题

1. **多模态解析缺失**：`app/tasks/knowledge_tasks.py` 中的 `parse_document_content` 函数对于 PDF、图片、音视频等格式仅预留了接口，实际仍作为纯文本处理。需要接入 OCR、版面分析或语音识别等模型以支持多模态文档。
2. **切片管理后台未实现**：虽然 `KnowledgeChunk` 已持久化到 MySQL，但目前尚未提供 API 接口供前端管理和查看具体的切片结果。
3. **文件上传的安全性与清理**：`/upload` 接口将文件保存在 `./data/raw_data` 目录下，但未实现文件类型校验（防范恶意文件上传）和过期文件清理机制。
