## 研究问题

为 `knowledge_items` 添加一个文件路径字段，并相应地修改知识库录入逻辑，使 `content` 绝对是知识库内容，而将路径储存在专门的字段中。（若上传的不是文件，则新字段为空）

## 发现摘要

1. 需要在 `app/models/knowledge.py` 的 `KnowledgeItem` 模型中新增 `file_path` 字段（`String` 类型，允许为空）。
2. 需要在 `app/schemas/knowledge.py` 的相关 Pydantic 模型（如 `KnowledgeItemBase`, `KnowledgeItemCreate`, `KnowledgeItemUpdate`）中新增 `file_path` 字段。
3. 需要修改 `app/api/v1/routes/knowledge.py` 中的 `/upload` 接口，在处理文件上传时，将文件保存到本地，并将路径赋值给 `file_path`。对于纯文本上传，同样将其保存为 `.txt` 文件，并将该文件的路径赋值给 `file_path`。
4. 需要修改 `app/tasks/knowledge_tasks.py` 中的 `parse_document_content` 和 `process_knowledge_document`，因为 `content` 已经是实际内容，不再需要从 `content` 中判断是否为文件路径并读取。如果需要处理多模态文件，可以通过 `file_path` 字段获取文件进行处理。

## 当前实现分析

目前在 `app/api/v1/routes/knowledge.py` 的 `/upload` 接口中：
- 如果上传的是纯文本（`text_content`），会将其保存为 `.txt` 文件，并将纯文本内容作为 `content` 存入数据库。
- 如果上传的是文件（`file`），会将文件保存到本地，并将**文件路径**作为 `content` 存入数据库。

在 `app/tasks/knowledge_tasks.py` 中：
- `parse_document_content` 函数会判断 `content` 是否为存在的文件路径，如果是，则读取文件内容。这导致 `content` 字段的语义不明确（既可能是内容，也可能是路径）。

### 核心流程

**修改后的流程设计：**

1. **API 接收请求 (`/upload`)**:
   - **纯文本上传**: 将文本保存为本地 `.txt` 文件，将文本内容作为 `content`，并将生成的 `.txt` 文件路径赋值给 `file_path`。
   - **文件上传**: 将文件保存到本地，记录路径为 `file_path`。
     - 如果是纯文本文件（如 `.txt`），可以在接口中直接读取内容并赋值给 `content`。
     - 如果是多模态文件（如 `.pdf`, `.png`），在接口中无法立即提取文本，此时 `content` 暂存为空字符串，由后续的异步任务提取。
2. **数据库存储**:
   - 创建 `KnowledgeItem` 记录，保存 `content` 和 `file_path`。
3. **异步任务处理 (`process_knowledge_document`)**:
   - 任务读取 `KnowledgeItem`。
   - 如果 `content` 为空且 `file_path` 存在（例如多模态文件），则通过 `file_path` 读取文件并提取文本，然后更新数据库中的 `content` 字段。
   - 直接使用 `content` 进行切片和向量化。

## 架构洞察

- **职责分离**: 明确 `content` 和 `file_path` 的职责分离，有助于统一数据模型，避免在后续处理中频繁判断 `content` 的类型（是路径还是文本）。
- **异步解析**: 对于大文件或多模态文件，在 API 接口中同步读取和提取文本可能会导致请求超时。建议在 API 接口中仅保存文件并设置 `content` 为空或占位符，然后在 Celery 异步任务中通过 `file_path` 提取文本并更新到数据库的 `content` 字段。

## 潜在风险和边缘情况

- **大文件读取**: 如果在 `/upload` 接口中直接 `await file.read()` 并将其作为字符串存入 `content`，对于非常大的文本文件可能会占用大量内存。
- **多模态文件**: 对于 PDF、图片等非纯文本文件，直接读取的二进制内容不能存入 `content`（Text 类型）。必须在存入前进行解析，或者先存入空字符串，由异步任务解析后更新。
- **数据库迁移**: 新增 `file_path` 字段需要生成并应用 Alembic 迁移脚本，否则会导致数据库操作失败。

## 开放问题

（已全部澄清）
1. **多模态文件处理**: 确认在 `/upload` 接口中 `content` 存空字符串，由 Celery 异步任务解析后更新。
