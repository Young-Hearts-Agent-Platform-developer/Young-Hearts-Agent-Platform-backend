## 研究问题

确认已经通过 `upload` 接口上传了一个测试知识数据（数据库中已存在记录），但执行 `chromadb_connection.py` 脚本后显示 ChromaDB 中没有任何集合和数据。为什么会发生这种情况？
另外，启动 Celery Worker 后，日志中出现大量 `ERROR/MainProcess] Document <id> not found.` 报错，这是什么原因？

## 发现摘要

1. **异步处理机制**：知识库的上传接口（`upload`）仅负责将文件保存到本地并将元数据同步写入 MySQL 数据库，随后通过 Celery 触发异步任务（`process_knowledge_document`）进行文档切片和向量化入库。
2. **Celery Worker 未启动**：在本地开发环境中，如果未单独启动 Celery Worker 进程，异步任务会被积压在 Redis 消息队列中，导致 ChromaDB 无法接收到向量化后的数据。
3. **历史任务积压清理**：启动 Worker 后出现的大量 `Document not found` 报错，是因为 Redis 队列中积压了大量历史测试任务，而这些任务对应的 MySQL 数据库记录已被删除或重置。Worker 正在正常清理这些“幽灵”任务。
3. **端口配置一致性**：应用配置（`.env`）和测试脚本均指向 `8001` 端口，排除了连接到不同 ChromaDB 实例的可能性。

## 当前实现分析

### 核心流程

当用户调用 `/api/v1/knowledge/upload` 接口上传文件时，系统执行以下流程：

1. **同步阶段（API 响应前）**：
   - 接收文件并保存到本地目录 `data/raw_data/`。
   - 构建 `KnowledgeItemCreate` 对象，并强制设置 `status="published"`。
   - 调用 `knowledge_service.create_item` 将记录同步保存到 MySQL 数据库（此时前端收到成功响应，数据库中可见该记录）。
2. **异步触发阶段**：
   - `create_item` 方法检测到 `status == "published"`，调用 `process_knowledge_document.delay(item.id)` 将任务推送到 Redis 队列。
3. **异步执行阶段（需 Celery Worker 参与）**：
   - Celery Worker 从 Redis 队列中取出任务。
   - 读取文件内容，调用 `CustomSplitter` 进行文本切片。
   - 调用 `DoubaoEmbeddings` 生成向量。
   - 将向量数据存入 ChromaDB 的 `knowledge_base` 集合中。

## 架构洞察

- **解耦设计**：上传与向量化分离的设计是合理的，避免了处理大文件或调用外部大模型 API 时导致 HTTP 请求超时。
- **依赖要求**：这种设计强依赖于后台任务队列（Redis + Celery）的正常运行。在本地开发或测试时，容易因为忘记启动 Worker 而导致“数据只进了一半”的假象。

## 潜在风险和边缘情况

- **任务静默失败**：如果 Celery Worker 启动了但处理过程中发生异常（如大模型 API Key 无效、ChromaDB 连接失败），任务会失败并将数据库中的 `status` 更新为 `failed`。但如果 Worker 根本没启动，任务会一直处于 `pending` 状态，数据库中的 `status` 仍为 `published`，导致状态不一致。
- **Redis 积压与启动风暴**：如果长期不启动 Worker，Redis 队列中会积压大量任务。一旦启动，Worker 会瞬间消费这些任务。如果这些任务对应的数据库记录已被删除（如重置了数据库），Worker 会抛出大量 `Document <id> not found` 错误。这属于正常的“队列清理”行为，任务会捕获异常并快速结束（`succeeded in 0.0s`），不会影响后续新任务的执行。

## 解决方案与操作建议

要解决当前 ChromaDB 中无数据的问题，请在终端中启动 Celery Worker 进程：

1. 确保 Redis 服务已启动并在 `localhost:6379` 运行。
2. 打开一个新的终端窗口，激活虚拟环境。
3. 运行以下命令启动 Celery Worker（Windows 环境下建议加上 `--pool=solo`）：
   ```bash
   celery -A app.tasks.knowledge_tasks worker --loglevel=info --pool=solo
   ```
4. Worker 启动后，会自动消费 Redis 中积压的任务，你将在终端看到文档被切片并存入 ChromaDB 的日志。
5. 再次运行 `chromadb_connection.py` 脚本，即可看到数据。
