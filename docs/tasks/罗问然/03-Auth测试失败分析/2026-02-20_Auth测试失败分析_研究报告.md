# Auth 模块 Test 失败分析与修复建议

## 版本记录

| 日期 | 版本 | 修改内容 | 修改原因 |
|---|---|---|---|
| 2026-02-20 | v1.0 | 初始分析 | pytest 失败分析 |

## 研究问题

根据 pytest 输出结果，分析 `tests/test_auth.py` 和 `tests/test_auth_security.py` 中的失败原因。
错误信息主要是：
- `test_register_and_login`: 422 Unprocessable Entity instead of 200 OK
- `test_me_info`: 401 Unauthorized instead of 200 OK
- `test_session_expired_sim`: 401 Unauthorized instead of 200 OK

## 发现摘要

核心问题在于注册接口 (`/api/auth/register`) 的请求体 Schema (`UserRegisterRequest`) 定义了必填字段 `roles`，但测试辅助函数 `register_user` 在默认情况下未传递该字段，导致注册失败 (422)。由于注册失败，后续依赖该用户的登录和信息获取测试自然失败 (401)。

## 当前实现分析

1.  **测试代码 (`tests/test_auth.py`)**:
    ```python
    def register_user(client, username, password, roles=None):
        data = {"username": username, "password": password}
        if roles:
            data["roles"] = roles
        return client.post("/api/auth/register", json=data)
    ```
    当调用 `register_user(client, "user1", "pass1234")` 时，`roles` 为 `None`，也就是请求体中**不包含** `roles` 字段。

2.  **Schema 定义 (`app/schemas/user.py`)**:
    ```python
    class UserRegisterRequest(BaseModel):
        username: str
        password: str
        # ... 其他可选字段 ...
        roles: List[UserRole]  # 必填字段，无默认值
        # ...
    ```
    `roles` 定义为必须字段。因此，缺少该字段的请求会被 FastAPI (Pydantic) 拒绝，返回 422。

3.  **连锁反应**:
    - `test_register_and_login` 断言注册返回 200，实际返回 422 -> **FAIL**
    - `test_me_info` 先调用注册（失败），再调用登录。由于用户未创建，登录失败（或实际上如果注册没成功，数据库里没这个用户），返回 401 -> **FAIL**
    - `test_session_expired_sim` 同理 -> **FAIL**

## 修复建议

建议修改 `app/schemas/user.py` 中的 `UserRegisterRequest`，为 `roles` 字段提供默认值。考虑到平台业务背景，普通注册用户通常默认为 "family" (家属) 角色。

**修改前**:
```python
roles: List[UserRole]
```

**修改后**:
```python
roles: List[UserRole] = ["family"]
```

## 验证计划

1. 修改 `app/schemas/user.py`.
2. 再次运行 `pytest tests/test_auth.py tests/test_auth_security.py`.
