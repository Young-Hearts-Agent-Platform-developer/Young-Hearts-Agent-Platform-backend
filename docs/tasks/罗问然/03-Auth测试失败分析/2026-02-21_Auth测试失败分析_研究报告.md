## 研究问题

根据 pytest 输出结果，分析 `tests/test_auth.py` 中的失败原因。
错误信息主要是：
- `test_register_and_login`: `AssertionError: assert 'session_id' in <Cookies[]>`。注册和登录请求均返回 200 OK，但响应中未设置 `session_id` Cookie。
- `test_me_info`: `AssertionError: assert 401 == 200`。由于登录时未获取到 Session Cookie，后续获取用户信息的请求因未鉴权而失败。

## 发现摘要

1.  **v1.0 发现回顾**: 注册接口曾因缺少 `roles` 字段返回 422。目前该问题在测试中似乎已解决或绕过（测试用例通过了注册步骤），但值得保留关注。
2.  **v1.1 新发现**: `login` 接口的实现逻辑中，仅当请求头 `User-Agent` 包含 "web" 字符串（不区分大小写）时，才会设置 `session_id` Cookie。
    - 测试辅助函数 `login_user` 默认不发送 `User-Agent`，导致后端判断为非 Web 端请求，未下发 Cookie。
    - 测试用例 `test_register_and_login` 期望在 Cookie 中找到 `session_id`，因此断言失败。
    - 测试用例 `test_me_info` 依赖登录状态，由于未获取 Cookie，后续请求无法通过鉴权。

## 当前实现分析

1.  **后端登录逻辑 (`app/api/v1/routes/auth.py`)**:
    ```python
    @router.post("/login", response_model=LoginResponse)
    async def login(user_in: UserLogin, response: Response, request: Request):
        # ... 登录验证 ...
        user_agent = request.headers.get("user-agent", "")
        # 简单判断：web端用cookie，app端返回session_id
        if "web" in user_agent.lower():
            # 使用 SameSite=None 时需要同时设置 Secure=True
            response.set_cookie(key="session_id", value=session_id, ...)
        return LoginResponse(user=user, session_id=session_id)
    ```
    代码明确要求 `User-Agent` 必须包含 "web" 才会设置 Cookie。

2.  **测试辅助函数 (`tests/test_auth.py`)**:
    ```python
    def login_user(client, username, password, user_agent=None):
        headers = {"User-Agent": user_agent} if user_agent else {}
        return client.post("/api/auth/login", json={"username": username, "password": password}, headers=headers)
    ```
    当 `user_agent` 参数为 `None` (默认值) 时，请求头为空（或仅包含 TestClient 默认头，通常不包含 "web"）。

3.  **失败测试用例 (`test_me_info`)**:
    ```python
    def test_me_info(client):
        # ...
        resp = login_user(client, "user2", "pass5678")
        assert resp.status_code == 200
        # 获取当前用户信息
        resp2 = client.get("/api/auth/me") # 这里没有显式传递 cookie，依赖 client 自动管理
        assert resp2.status_code == 200    # 实际返回 401
    ```
    由于 `login_user` 没拿到 Cookie，`client` 的 Cookie Jar 是空的，导致 `/me` 请求没有 Session ID。

## 修复建议

建议修改测试代码 `tests/test_auth.py` 中的 `login_user` 辅助函数，使其默认模拟 Web 端请求，以便后端正确设置 Cookie。

**修改方案**:
在 `login_user` 函数中，若未传入 `user_agent`，则默认设置一个包含 "web" 的 User-Agent，例如 `"TestWebClient"`.

```python
def login_user(client, username, password, user_agent=None):
    # 默认模拟 Web 端，确保获取 Cookie
    if user_agent is None:
        user_agent = "TestWebClient"
    
    headers = {"User-Agent": user_agent}
    return client.post("/api/auth/login", json={"username": username, "password": password}, headers=headers)
```

这样修改后，现有测试用例无需改动即可通过，同时也符合后端“区分端侧”的设计意图。
