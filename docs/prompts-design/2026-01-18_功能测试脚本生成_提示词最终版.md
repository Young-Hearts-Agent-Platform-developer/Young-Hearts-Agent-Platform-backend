# 功能测试脚本生成 提示词（设计）完整报告
## 报告日期
2026-01-18

## 核心需求
设计一个自定义提示词，接受用户输入的后端功能，自动检索相关代码并在 test/ 目录下新建详细注释的测试脚本（不使用 pytest），可直接测试该功能。

## 目标文件上下文详情
- 文件路径：.github/prompts/功能测试脚本生成.prompt.md （提示词正文请直接参考此文件）
- 文件用途：用于自动生成后端功能的标准 Python 测试脚本，便于开发者快速验证功能实现，提升测试覆盖率与可维护性。
- 上下文核心：
  - 采用 YAML frontmatter 规范，包含 name、description、argument-hint、agent、model、tools 字段
  - 结构化分为角色、原则、输入要求、流程、输出标准五大模块
  - 测试脚本需放在 test/ 目录，命名为 test_功能名.py，脚本需详细注释且不依赖 pytest
- 适配逻辑：提示词内容与文件格式、字段、流程完全匹配，术语与项目结构保持一致，输出标准与实际开发需求对齐。

## 设计/优化详情
### 核心设计思路
- 角色定义：定位为后端功能测试脚本生成工程师，强调 Python 能力与代码库分析能力，语气专业、流程清晰
- 流程拆解：从功能解析、代码检索、依赖分析到脚本生成，确保每步可执行且易追溯
- 约束设定：强制不使用 pytest，注重注释与可运行性，脚本结构与 test/ 目录规范一致

- 模拟输出示例：
  用户输入“用户注册”，AI自动检索 user_service.py、user.py 等相关代码，生成 test/test_用户注册.py，脚本包含详细注释，测试主流程与边界情况，运行后输出注册结果与异常处理。
- 验证维度：
  - 需求匹配度：✓ 符合（完全满足自动生成测试脚本需求）
  - 上下文适配度：✓ 贴合（文件结构、字段、流程均匹配项目实际）
  - 角色清晰度：✓ 清晰（专业测试脚本工程师，定位明确）
  - 流程可执行性：✓ 可执行（每步均有明确指引，易于落地）
  - 输出合规性：✓ 合规（脚本结构、注释、可运行性均达标）

## 使用指南
- 适用场景：后端功能开发完成后，需快速验证功能实现、覆盖主流程与边界情况，提升测试效率与代码质量
- 调整建议：如需适配其他语言或测试框架，仅需调整脚本生成部分，保留整体流程结构
- 常见问题：如功能描述不明确，建议用户补充具体流程或关键参数；如依赖复杂，脚本需在注释中说明依赖关系
